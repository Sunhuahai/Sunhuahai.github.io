工具与工作流

语音输入法的革命：从打字到 Vibe Coding

2026-06-24 4 分钟阅读

最近重新使用语音输入之后，我越来越觉得它改变的并不只是输入速度，而是改变了人和工具之间的表达方式。过去的语音输入更像一个听写软件：你说什么，它尽量逐字记下来。问题是人说话时天然会有停顿、重复和语气助词，这些东西在口语里不明显，落到文字里却会非常刺眼。

豆包输入法这类新工具真正有意思的地方，是它会轻度整理口语。它会删掉一部分“嗯”“啊”之类的填充词，顺手修正明显不连贯的表达，让一段随口说出来的话更接近可以直接使用的文本。它不是替你写文章，而是把粗糙的口语先打磨到能进入下一步编辑的程度。

它为什么适合 Vibe Coding

Vibe Coding 对输入的要求很特别：它不一定要求每个词都极端精确，却要求输入量足够大、上下文足够连续、意图足够完整。传统打字在这里会慢下来，因为人往往还没把想法说完，手已经跟不上了。语音输入则刚好相反，它允许人先把一整段想法倾倒出来，再交给模型和自己一起整理。

这也是它和传统语音输入最大的区别。过去的语音文本常常充满无意义的口头残留，不仅浪费 token，也会干扰模型理解。现在的自动整理相当于在输入端做了一层清洗：保留大意，减少噪音，让 prompt 更像人的真实意图，而不是一次笨拙的逐字记录。

它也改变了日记

我在日记里第一次尝试 Typeless 时，最直观的感受是记录欲望变强了。打字时人容易一边写一边审查自己，话还没出来就被删掉；语音输入则更像把念头先接住。很多时候，思想不是先完整形成再被写下来，而是在表达过程中逐渐成形。

这对日记很重要。日记不需要像论文那样准确，也不需要像正式文章那样漂亮，它首先需要把当下的状态保存下来。语音输入降低了这件事的启动成本，也让许多本来会消失的念头有机会被留下。

边界在哪里

当然，语音输入并不适合所有场景。代码、公式、命令行、精确文件路径仍然更适合键盘。它真正擅长的是“大量、连续、低精度”的输入：构思文章、写日记、描述需求、和 AI 讨论方案。它像一个入口，把脑内还没有完全成形的东西先转成文本。

所以我愿意把语音输入看作一种写作和编程工作流的基础设施。它没有替代思考，恰恰相反，它让思考更容易被捕捉、被整理、被继续推进。
